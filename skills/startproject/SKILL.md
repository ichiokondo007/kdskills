# startproject

## 目的

プロジェクトの土台(フォルダ、`docs/`、`プロジェクト概要書.md`、Git の main と初回コミット)を作り、利用者の頭の中を概要書に明文化する。
やるのはこの 2 つだけ。要件定義や画面設計などの後続工程は別スキルが担当する。

## 引数の確認

1. `<name>` が無ければ「プロジェクト名を教えてください(英数字、ハイフン、アンダースコア)」と聞いて止まる。
2. `<name>` が `^[A-Za-z0-9_-]+$` に合わなければ、「プロジェクト名には英数字、ハイフン、アンダースコアのみ使えます: `<name>`」と示して止まる。フォルダは作らない。
3. 現在のディレクトリが既に Git リポジトリの中なら(`git rev-parse --is-inside-work-tree` が `true`)、「入れ子の Git リポジトリになります」と 1 行伝えて続行する。

## モード判定

`./<name>` が無ければ **新規モード**、あれば **再開モード**。

## 新規モード

テンプレートはこの SKILL.md と同じディレクトリの `templates/` にある(スキル起動時に示される Base directory を使う)。

1. 今日の日付を取る: `date +%Y-%m-%d`。推測で書かない。
2. 次を作る。
   - `<name>/docs/.gitkeep`(空ファイル)
   - `<name>/プロジェクト概要書.md`: `templates/プロジェクト概要書.md` をコピーし、`<name>` をプロジェクト名に、`YYYY-MM-DD`(2 箇所)を今日の日付に置換する。それ以外は変えない
   - `<name>/.gitignore`: `templates/gitignore` をそのままコピーして改名する
3. `<name>/` で次を実行する。
   ```bash
   git init -b main && git add -A && git commit -m init
   ```
4. 「`<name>/` に土台を作り、main に `init` をコミットしました」と 1 行報告してから、埋め込みフェーズへ進む。

## 再開モード

1. `<name>/プロジェクト概要書.md` を読む。無い場合、または `## 1.` 〜 `## 11.` の 11 個の見出しが揃っていない場合は「`<name>/` は kdskills の概要書ではないようです。作り直しはしません」と伝えて止まる。何も書かない。
2. 項目 1〜9 の `**状態**:` 行を読み、状態ごとの件数と項目名を一覧で見せる。
   `**状態**:` の語が `決定` / `検討中` / `未着手` 以外の項目は `検討中` として扱う。本文は書き換えず、埋め込みフェーズで聞き直す。
3. 埋め込みフェーズへ進む。対象は `検討中` と `未着手` の項目だけ。ブレインダンプの質問はしない。

## 埋め込みフェーズ

1. **新規モードのときだけ**、最初に一度だけ聞く:
   「今、頭にあることを順不同で全部書いてください。決まっていないことも、候補や迷いもそのままで構いません」
2. 新規モードでは、答えを 11 項目に振り分けて概要書に書き込み、「埋まった項目 / 空の項目」を一覧で見せる。再開モードでは手順 2 で見せた一覧がこれに当たる。
3. 空の項目(`検討中` と `未着手`)を項目番号の若い順に 1 つずつ聞く。1 メッセージ 1 項目。
   - 項目 3(ゴール)は「確認できる形で」と促す
   - 項目 6(主要機能)は 1 行 1 機能で箇条書きにする
   - 項目 7(技術スタック)は区分ごとに聞く。未定の区分には候補と判断軸を提示してよい
   - `検討中` の項目は、残っている「候補:」「判断軸:」を示してから聞く
4. 答えは 3 通りに分ける。
   - 決まった → `**状態**: 決定` にして本文を書く
   - 候補段階 → `**状態**: 検討中` にして、本文に「候補: A / B」「判断軸: …」の 2 行を必ず残す
   - 「飛ばす」「後で」「わからない」→ `未着手` のまま次の項目へ
5. 1 項目答えるごとに概要書へ書き込む。まとめて書かない。
6. 利用者が「ここまでで終わり」「一旦終了」など終了の意思を示したら、残りは聞かずに終了処理へ進む。項目 9 まで聞き終えた場合も同じ。

## 終了処理

1. 項目 7 の状態を決める: 表の 5 行すべてが `決定` なら `決定`。そうでなければ行の中で重い方(`未着手` > `検討中`)。
2. 項目 10 `未決事項` の表を書き直す。`検討中` と `未着手` の項目を 1 行ずつ「項目 | 状態 | 何が決まっていないか」で並べる。全項目 `決定` なら「なし」と 1 行書く。
3. 項目 11 `次のアクション` が空なら、1〜3 個提案して利用者に確認し、了承されたものだけ書く。
4. 先頭の表を更新する: 最終更新を今日の日付に、決定 / 検討中 / 未着手 の件数を項目 1〜9 で数え直す。
5. `<name>/` で次を実行する。
   ```bash
   git add プロジェクト概要書.md && git commit -m "docs: 概要書を更新"
   ```
   worktree は使わない。概要書は main が正本。
6. 「概要書を更新してコミットしました。未決事項: N 件」と 1 行報告する。

## やらないこと

- `docs/` 配下のサブフォルダを作らない(後続スキルの仕事)
- GitHub へのリポジトリ作成や push をしない
- 概要書以外の文書(要件定義など)を作らない
- 既存フォルダを作り直したり、概要書の見出し構造を変えたりしない

## 失敗時

| 状況 | 対応 |
|---|---|
| `<name>` 未指定 | 名前を聞いて止まる |
| `<name>` に許可外の文字 | 理由を示して止まる。フォルダは作らない |
| `git` が無い、`git init` 失敗 | フォルダと文書は残し、Git 部分だけ失敗したと報告して止まる |
| 再開モードで概要書が無い / 見出し不一致 | 「kdskills の概要書ではないようです」と止める |
| `git commit` が identity 未設定で失敗 | 概要書は残る。次を示して止まる: `git config --global user.name "名前"` と `git config --global user.email "メール"` |
